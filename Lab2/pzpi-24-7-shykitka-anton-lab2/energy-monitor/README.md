# EnergyMonitor — Програмна система для контролю енергоспоживання будинку

Монорепозиторій програмної системи для моніторингу, аналізу та оптимізації витрат електроенергії в житлових і комерційних приміщеннях. Проєкт побудовано на модульній архітектурі вертикальних зрізів (*Vertical Slice Architecture*) із асинхронною серверною частиною на **FastAPI**, реляційною СУБД **PostgreSQL 18**, зворотним проксі-сервером **Traefik v3** та підтримкою інтеграції з IoT-модулями на базі **ESP32**.

---

## 🛠 Технологічний стек

### 🌐 Інфраструктура та мережа
- **Docker Compose** (`compose.yml`, `compose.dev.yml`): оркестрація контейнерів `db` (PostgreSQL 18), `traefik`, `mailpit` та `pgweb`.
- **PostgreSQL 18** (`127.0.0.1:5433`): реляційна СУБД із асинхронним пулом з'єднань через `asyncpg`.
- **Traefik v3** (`8880` / `8443`): зворотний проксі-сервер із маршрутизацією піддоменів та локальним TLS/SSL через `mkcert`.
- **pgweb** (`http://127.0.0.1:8082` або `https://db.energymon.localhost:8443`): вебінтерфейс для перегляду таблиць і даних PostgreSQL.
- **Mailpit** (`http://127.0.0.1:8026` або `https://mail.energymon.localhost:8443`, SMTP `1026`): локальний тестовий поштовий сервер.

### 🐍 Серверна частина (`backend/`)
- **Python 3.14 + FastAPI** (`http://127.0.0.1:8080`, Swagger UI: `/docs`, ReDoc: `/redoc`)
- **Менеджер пакетів:** `uv`
- **ORM і база даних:** **SQLAlchemy 2 (asyncio)** + **asyncpg** (12 таблиць із первинними ключами `UUIDv7` та часовими мітками в `UTC`).
- **Міграції схеми БД:** **Alembic** (асинхронний режим).
- **Безпека та автентифікація:**
  - Хешування паролів: **Argon2id** (`pwdlib[argon2]`).
  - Сесії користувачів: **JWT** (`pyjwt[crypto]`) із `jti` та ротацією `refresh_token` у базі даних (`HttpOnly SameSite=Lax` cookie для вебу + Bearer/JSON для мобільного клієнта).
  - Автентифікація IoT-пристроїв ESP32: окремий заголовок `X-Device-Token` (`em_iot_...`), хеш якого (`SHA-256`) зберігається в таблиці `power_lines`.
- **Архітектура:**
  ```text
  backend/app/
  ├── core/       # конфігурація, підключення до БД, базові міксини (UUIDMixin, TimestampMixin),
  │               # узагальнений BaseRepository, винятки, криптографія та поштовий сервіс
  └── modules/    # ізольовані бізнес-модулі (models, schemas, repository, service, dependencies, router):
      ├── health        # перевірка стану сервера та з'єднання з PostgreSQL
      ├── auth          # реєстрація, вхід, ротація JWT refresh-токенів, вихід
      ├── users         # профіль, ролі (User/Admin), підписки (Free/Pro), локалізація (uk/en, UTC, Metric/Imperial)
      ├── tariffs       # однозонні та двозонні («день/ніч», коефіцієнт 0.5) тарифні плани
      ├── lines         # лінії живлення та реєстрація сенсорів ESP32
      ├── budgets       # місячні фінансові ліміти, облік витрат, прогноз і пороги 80% / 100%
      ├── telemetry     # прийом пакетів від ESP32, контроль пропусків (Time-gap), профілі навантаження
      ├── anomalies     # фіксація стрибків ΔP та перевантажень, маркування приладів, пояснення LLM
      ├── notifications # токени push-сповіщень (FCM / APNs) та журнал попереджень
      └── admin         # журнал аудиту, резервні копії з SHA-256, експорт/імпорт конфігурацій
  ```
- **Контроль якості коду:** `ruff` (лінтер і форматування), `ty` (статична перевірка типів), `pytest` + `httpx` (асинхронні інтеграційні тести).

### 🔌 Заплановані клієнтські та апаратні компоненти (наступні етапи)
- **IoT-клієнт (`iot/`):** мікроконтролер **ESP32** (C++, емуляція у Wokwi та фізичний низьковольтний стенд), розрахунок RMS і активної потужності, кільцевий буфер у RAM при втраті Wi-Fi.
- **Вебклієнт (`frontend/`):** React 19 + TypeScript + Vite + Tailwind CSS + shadcn/ui.
- **Мобільний клієнт (`mobile/`):** Capacitor 8 на спільній кодовій базі React для Android та iOS.

## 🚀 Швидкий старт

Переконайтеся, що у вас встановлені **Docker Desktop**, **uv**, **pnpm** (та **mkcert** за потреби локального HTTPS).

### 1. Налаштування змінних середовища та сертифікатів

Скопіюйте шаблон змінних оточення (якщо `.env` ще не створено):

```powershell
cp .env.example .env
```

За потреби згенеруйте локальні SSL-сертифікати і встановіть залежності:

```powershell
pnpm run setup
```

*(Або лише залежності Python без сертифікатів: `cd backend && uv sync`.)*

### 2. Запуск інфраструктури (Docker)

```powershell
pnpm docker:up
```

Команда запускає контейнери `energymon-db` (PostgreSQL 18 на порту `5433`), `energymon-pgweb` (`8082`), `energymon-mailpit` (`8026`) та `energymon-traefik` (`8880` / `8443`).

### 3. Застосування міграцій бази даних

```powershell
pnpm migrate
```

Або безпосередньо з директорії `backend/`:

```powershell
cd backend
uv run alembic upgrade head
```

### 4. Запуск сервера розробки

```powershell
pnpm dev:backend
```

Після запуску доступні:
- **Swagger UI (інтерактивна документація API):** `http://127.0.0.1:8080/docs`
- **ReDoc:** `http://127.0.0.1:8080/redoc`
- **OpenAPI JSON:** `http://127.0.0.1:8080/openapi.json`
- **pgweb (вебклієнт PostgreSQL):** `http://127.0.0.1:8082`

## 📜 Основні команди (`package.json`)

| Команда | Опис |
| :--- | :--- |
| `pnpm run setup` | Генерація локальних SSL-сертифікатів (`mkcert`) та `uv sync` |
| `pnpm docker:up` | Запуск PostgreSQL 18, Traefik v3, Mailpit і pgweb у фоновому режимі |
| `pnpm docker:down` | Зупинка Docker-контейнерів |
| `pnpm docker:down:v` | Зупинка контейнерів із видаленням томів (`pgdata`) |
| `pnpm migrate` | Застосування міграцій Alembic (`alembic upgrade head`) |
| `pnpm dev:backend` | Запуск FastAPI-сервера розробки на порту `8080` |
| `pnpm generate:api` | Експорт актуальної специфікації `openapi.json` |
| `pnpm lint:backend` | Статичний аналіз коду (`ruff check .` та `ty check app`) |
| `pnpm format:backend` | Автоформатування коду (`ruff format .`) |
| `pnpm test:backend` | Запуск інтеграційних тестів (`pytest`) |

## 🔒 Безпека, інтернаціоналізація та взаємодія з IoT

- **Користувачі:** паролі зберігаються виключно у вигляді хешу **Argon2id**. Кожен запит `/api/v1/auth/refresh` інвалідує старий `refresh_token` у БД та випускає нову пару токенів. Підтримується м'яке видалення облікового запису з анонімізацією даних (GDPR).
- **IoT-пристрої (ESP32):** під час створення лінії живлення (`POST /api/v1/lines`) сервер одноразово повертає секретний ключ `device_api_token` (`em_iot_...`). Пристрій передає його у заголовку `X-Device-Token` на `POST /api/v1/telemetry/ingest`.
- **Інтернаціоналізація:** усі часові мітки в базі даних зберігаються в **UTC (`TIMESTAMPTZ`)**, а користувачі мають налаштування мови (`uk` / `en`), часового поясу (`Europe/Kyiv`) та системи одиниць вимірювання (`Metric` / `Imperial`).
